# Diff 알고리즘

> 이 문서를 읽으면 두 VNode에서 어떤 Patch 목록이 나와야 하는지 알고, DOM 없이 `diff`를 구현하고 테스트할 수 있어요.

| 항목 | 내용 |
|---|---|
| 상태 | 공통 형식 합의 완료 ([vnode-spec.md](vnode-spec.md)) |
| 다루는 요구사항 | R1-2, R3-2 |
| 관련 이슈 | #5 |
| 소스 파일 | `src/diff.ts`, `src/diff.test.ts` |

Patch 형식과 출력 순서의 약속은 [vnode-spec.md](vnode-spec.md#diff와-patch-사이의-약속)를 봐 주세요.

## 함수

| 함수 | 입력 | 출력 |
|---|---|---|
| `diff(oldV, newV)` | `oldV`, `newV: VNode`: 컴포넌트가 없는 트리 | `Patch[]`. 변경이 없으면 `[]` |
| `lis(arr)` | `arr: number[]`: 값 0은 제외 대상 | 최장 증가 부분수열의 **인덱스** 배열. (예: `lis([5, 3, 4, 0])` → `[1, 2]`) |

`src/diff.ts`는 DOM을 쓰지 않아요. 내부 함수 구성은 [phase-1-plan.md](phase-1-plan.md#노도현-srcdiffts)를 봐 주세요.

## 노드 비교

`diffNode(o, n, path, out)`의 순서예요.

1. `o === n`이면 끝이에요. VNode가 불변이라 같은 객체면 서브트리 전체가 같아요.
2. `type`이나 `key`가 다르면 `REPLACE`를 내고 끝이에요. 안쪽은 보지 않아요.
3. 텍스트 VNode면 내용이 다를 때 `TEXT`를 내고 끝이에요.
4. 자식을 비교해요. 그다음 속성을 비교해요.

**속성 비교**: 새 `props`에서 값이 `!==`로 다른 것은 `set`에, 이전에만 있는 것은 `remove`에 넣어요. 둘 다 비면 `PROPS`를 내지 않아요.

**경로 배열**: 배열 하나를 `push`와 `pop`으로 재사용하고 Patch를 낼 때만 복사해요. 노드마다 복사하면 전체가 O(n × 깊이)가 되기 때문이에요.

## 자식 비교: 9가지 조합

| 이전 ＼ 새 | 없음 | 텍스트 | 배열 |
|---|---|---|---|
| **없음** | Patch 없음 | `TEXT` | 전부 `CREATE` |
| **텍스트** | `TEXT` (빈 문자열) | 다르면 `TEXT` | `TEXT` (빈 문자열) 후 전부 `CREATE` |
| **배열** | 전부 `REMOVE` | 전부 `REMOVE` 후 `TEXT` | 양쪽 모두 key가 없으면 위치 비교, 하나라도 있으면 key 비교 |

- 이전 텍스트가 빈 문자열이면 `TEXT` (빈 문자열)을 내지 않아요.
- `REMOVE`를 여러 개 낼 때는 뒤 인덱스부터 내요.

## 위치 비교

key가 없을 때 쓰는 기본 경로예요. DOM에서 읽은 VNode는 `data-key`가 없으면 여기로 와요.

1. 공통 길이만큼 같은 위치끼리 `diffNode`를 불러요.
2. 이전이 길면 남는 쪽을 `REMOVE`해요. 뒤 인덱스부터 내요.
3. 새것이 길면 남는 쪽을 `CREATE`해요. `index`는 새 위치예요.

한 부모 아래에 `REMOVE`와 `CREATE`가 함께 나오지 않아요.

**한계**: 맨 앞 형제가 사라지면 뒤 형제가 한 칸씩 당겨져 다른 태그끼리 비교되고 전부 `REPLACE`돼요. 이 장면은 시연에 써요([verify-page.md](verify-page.md#시연-시나리오)).

## key 비교

예시는 이전 `a b c d e f g`, 새것 `a b e c d h f g`예요.

| 단계 | 하는 일 | 예시에서 |
|---|---|---|
| 1. 앞 공통 구간 | 앞에서부터 `type`과 `key`가 같은 동안 `diffNode` 후 전진 | `a`, `b` |
| 2. 뒤 공통 구간 | 뒤에서부터 같은 동안 `diffNode` 후 후진 | `g`, `f`. 남은 구간은 이전 `c d e`, 새것 `e c d h` |
| 3. 한쪽 소진 | 이전이 바닥나면 남은 새것을 `CREATE`, 새것이 바닥나면 남은 이전을 뒤에서부터 `REMOVE`하고 끝 | 해당 없음 |
| 4. 짝 찾기 | 새 구간의 key → 인덱스 맵을 만들어요. 이전 구간의 노드마다 새 위치를 찾아 `diffNode`하고, 없으면 `REMOVE`해요. 위치 배열에 "이전 인덱스 + 1"을 적어요 | 맵 `{ e: 2, c: 3, d: 4, h: 5 }`, 위치 배열 `[5, 3, 4, 0]` |
| 5. 배치 | 위치 배열의 LIS에 속한 노드는 고정, 나머지는 `MOVE`, 값 0은 `CREATE`. 새 인덱스 오름차순으로 내요 | `c`, `d` 고정. `MOVE e (4 → 2)`, `CREATE h (5)` |

4단계의 세부 규칙이에요.

- **경로:** 짝지은 노드의 안쪽 비교는 옛 인덱스로 경로를 붙여요.
- **짝을 못 찾는 경우:** 새 위치가 없거나, 그 자리가 이미 찼거나, `type`이 다르면 `REMOVE`해요.
- **key 없는 노드:** 맵에 넣지 않아요. 아직 짝이 없는 같은 타입의 key 없는 새 노드를 앞에서부터 찾아요.
- **이동 판정:** 순회 중 "지금까지 본 새 인덱스 최댓값"보다 작은 값이 나오면 이동이 필요해요. 한 번도 없으면 LIS를 건너뛰고 `MOVE`를 내지 않아요.
- **조기 종료:** 짝지은 개수가 새 구간 길이에 도달하면 남은 이전 노드는 조회 없이 `REMOVE`해요.
- **중복 key:** `console.warn`으로 경고해요. 같은 새 노드에 두 번째로 짝지어지는 이전 노드는 `REMOVE`하고, 남는 새 노드는 `CREATE`해요.

`MOVE`의 `from`은 위치 배열 값 − 1이고, `to`는 새 구간 시작 + 구간 안의 위치예요.

## LIS

- `tails[len]`은 "길이 `len + 1`인 증가수열 중 끝값이 가장 작은 원소의 인덱스"예요. 원소마다 이진 탐색으로 자리를 찾아 갱신해요. 끝값이 작을수록 뒤에 더 많은 원소를 이을 수 있기 때문이에요.
- 각 원소의 직전 원소 인덱스를 `prev`에 저장하고, 마지막 원소부터 거꾸로 따라가 복원해요.
- 값 0은 새 노드이므로 건너뛰어요.

## 복잡도

| 연산 | 시간 | 추가 공간 |
|---|---|---|
| `diff` 전체 | O(n + Patch 수 × 깊이) | 재귀 O(깊이) + 경로 배열 1개 |
| 위치 비교 | O(m) | 없음 |
| key 비교, 1–3단계에서 끝남 | O(m) | 없음 |
| key 비교, 5단계까지 | O(m log m) | O(m) |
| key 있는 노드와 없는 노드가 섞임 | 탐색 최악 O(m²) | O(m) |

n은 노드 수, m은 한 부모의 자식 수예요.

## 엣지 케이스

| 상황 | 처리 |
|---|---|
| 변경 없음 | `[]` |
| 같은 VNode 객체 | 비교 없이 끝 |
| 같은 key, 다른 `type` | key 목록 안에서는 `REMOVE` + `CREATE`(4단계에서 짝을 맺지 않아요). 루트끼리 비교할 때는 `REPLACE` |
| 인덱스를 key로 사용 | 앞에 삽입하면 key가 전부 밀려 모든 노드가 다르게 비교돼요. 입력값 같은 DOM 상태가 다른 노드로 옮겨 붙어요 |
| 조건부 자식 `cond && h(A)` | `false`를 버리므로 뒤 형제의 위치가 바뀌어요. 필요하면 key를 붙여요 |
| 깊은 중첩 | 재귀라서 깊이에 한계가 있어요. Node 26.13.0에서 약 2,200 깊이부터 스택이 넘쳤어요(2026-11-07 측정). 브라우저는 측정하지 않았어요 |

## 테스트

`src/diff.test.ts`에서 `node:test`로 확인해요. `jsdom`을 쓰지 않아요. DOM 없이 도는 것 자체가 검사예요.

| 검사 | 기대값 |
|---|---|
| 변경 없음 | `[]` |
| [위치 비교 예시](vnode-spec.md#전체-예시) | 예시의 세 Patch와 정확히 같음 |
| [key 비교 예시](vnode-spec.md#전체-예시) | `MOVE` 1개(`from: 4`, `to: 2`), `CREATE` 1개(`index: 5`) |
| 다섯 경우 | `CREATE`, `REMOVE`, `REPLACE`, `TEXT`, `PROPS`가 각각 나옴 |
| 9가지 조합 | 위 표와 같음 |
| `lis([5, 3, 4, 0])` | `[1, 2]` |
| 깊은 중첩 | `div` 아래 `b` 999겹, 맨 안쪽 `i`의 텍스트만 바꾸면 `TEXT` 1개, `path`는 0이 1,000개. 바꾸지 않으면 `[]` |
| 직렬화 | 함수 props와 텍스트 VNode가 없는 Patch 목록은 JSON 왕복 후 같음. 텍스트 VNode의 `type`은 Symbol이라 사라져요 |
| 불변 | 모든 VNode를 `Object.freeze`해도 오류 없음 |

최소 이동은 `insertBefore` 호출 수가 아니라 `MOVE` 개수로 세요. `CREATE`도 `insertBefore`를 쓰기 때문이에요.

## 실제 React와 다른 점

- React는 앞에서부터 짝을 맞추다 어긋나면 key 맵으로 찾고, LIS를 쓰지 않아요. 이 구현은 Vue 3처럼 앞뒤 공통 구간을 줄인 뒤 LIS로 고정할 노드를 골라요.
- React는 key가 같으면 Fiber를 재사용하고, 이 구현은 경로 기반 Patch를 내요.
- 펼친 뒤에 비교하므로 컴포넌트 타입 비교가 없어요([component-hooks.md](component-hooks.md#실제-react와-다른-점)).
